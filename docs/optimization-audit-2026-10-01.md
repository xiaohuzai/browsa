# browsa 优化审查 · 2026-10-01

本轮聚焦现有输入、会话管理和附件管线的可靠性；视觉审查使用 dev-preview 的真实界面，在 390px 侧栏与较宽预览中检查。预览使用示例数据，尚未覆盖所有真实 Provider 和第三方站点。

## 已确认问题与修复

| 问题 | 触发方式 | 修复 |
| --- | --- | --- |
| 召回后编辑会丢文字 | 主输入框或追问卡按 ↑ 后输入、粘贴或删除 | 输入事件仅退出召回，保留当前文字；↓ 越过最新条目仍可恢复未编辑的原草稿 |
| 会话操作失败仍提示成功 | 置顶、重命名、删除或清空时存储失败 / 服务工作线程无响应 | 检查失败信封、显示错误、保留原状态，删除失败解除待删状态 |
| 退出重命名后刷新失败会卡住编辑框 | 取消或保存名称后列表查询失败 | 本地完成编辑状态收尾，再刷新；保留正确名称与操作入口 |
| 列表读取失败被误判为空列表 | GET_SESSIONS 失败或服务工作线程无响应 | 保留已有列表并显示错误，成功后才替换内容 |
| 迟到查询清空新列表或覆盖 Agent ID | 两次抽屉刷新重叠，首次 Agent 查询较慢 | 每次异步返回后校验刷新代次，丢弃过期结果 |
| 附件提前完成仍留下超时计时器 | PDF / Office 解析在超时前成功或失败 | 在解析结束时清除兜底计时器，保留超时回退 |

## UI/UX 建议

1. **窄侧栏优先保证当前模型可辨。** 390px 预览中顶部 Provider 名称已截断，型号和状态更难识别。建议评估把多选和视频时间线放进更多菜单，给当前 Provider 留出空间；选项完整信息继续保留。这需要先验证高频入口使用情况。
2. **重命名入口更容易找到。** 当前会话名双击或 F2 才能重命名，行内按钮只提供置顶、导出、删除。建议在会话操作菜单中加入“重命名”，继续保留已有快捷方式。
3. **附加后保留一条清楚的内容状态。** 继续沿用简洁 chip，让首次使用者容易确认刚附加的是正文、字幕还是截图；细节仍放进检查入口。现有界面已有附加 chip，这一项需结合真实首次使用反馈判断，避免增加常驻说明。

上述前两项已在后续界面整理中实施：当前模型独占首行，搜索/多选/设置收进更多面板，会话增加直接重命名。附加状态仍沿用现有 chip。具体界面与素材变更见 [界面优化](uiux-update-2026-10-01.md)。
