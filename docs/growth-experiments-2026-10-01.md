# browsa：先验证一群人的持续使用

这是一份待验证的推广方案。商店安装数、当前活跃人数和留存不能互相替代；本轮没有收集用户行为数据，也没有对外发帖、联络用户或改变无遥测承诺。

第一人群：已有模型 API、Ollama 或本地 CLI Agent，且经常阅读技术文档的开发者。第一轮中文市场为执行假设，七语资产保留；按反馈决定后续语言投入。定位：**把正在读的网页，交给你已经在用的 AI。** 核心结果是少搬运上下文、更快理解、带着讨论继续工作。

完整 Ink Press 片用于官网产品介绍，展示能力与故事。获客另用三条单任务短片，各只承诺一个结果：

| 短片 | 钩子 | 操作与结果 | 首次使用前提 |
| --- | --- | --- | --- |
| 读技术文档 | 看文档，还在反复复制粘贴？ | 附加 Transformer 文档，理解注意力，针对一句话追问 | 已连通自己的 AI |
| 播客时间线 | 这条笔记，能点回原片 | 点击 07:42，回到对应观点 | 可获得字幕/转写；音频转写配置因来源而异 |
| Agent 会话 | 这篇网页，接着交给现有 Agent | 复制同一会话 ID，在 Codex 中续接 | 已配置 Agent Bridge 和对应 Agent |

片中的前端操作来自真实浏览器插件代码；冻结回答、文章/播客内容及 Agent CLI 示意明确标 DEMO。本轮使用独立演示目录和端口3968运行已安装的 Agent Bridge，真实 Codex 生成三点注意力回答及追问，再退出桥接进程释放会话，用 `codex exec resume` 同一 ID 成功续接。证据在 store-assets/promo/growth-live/capture-live.json 和 verified-resume.json；短片标注真实回答、播放经过剪辑，CLI画面是实际命令/回答的重排展示。其他语言短片使用本地化演示数据，并明确标注。正式投放前，仍应让自愿参与者在自己的已配置后端完整跑通。不要编造在线耗时、工具成功结果或一键打开 Agent 能力。

## 可复现的首次任务

选择已有条件对应的路线，不先要求了解全部供应商：

- 已有 API：商店安装 → 设置填写 Base URL/API Key/Model → Ping → 下方测试问题。
- 已有 Ollama：启动本机 Ollama、确认已有模型 → 设置 `http://localhost:11434` 和已有模型 ID → Ping → 测试问题。是否需允许扩展来源，依实际部署检查。
- 已有 Codex/Claude Code/pi：使用 [连接指南的安装提示词](en/guide/providers.html#agent-bridge)，让自己的 CLI 完成桥接配置 → 填入最终 Bridge URL → Ping → 测试问题。

测试页面用官方公开技术资料，例如 [MDN WebAssembly.Memory.grow](https://developer.mozilla.org/en-US/docs/WebAssembly/Reference/JavaScript_interface/Memory/grow)。测试问题：“非共享 WebAssembly 内存扩容后，旧 Uint8Array 还能用吗？给我一个最短的正确示例。” 预期有用回答：旧 ArrayBuffer 被分离，重新创建 `new Uint8Array(memory.buffer)`；不能把 shared memory 的行为混为一谈。追问：“为什么 grow(0) 也需要考虑旧缓冲区？” 页面附加、回答、追问各验证一次；不要要求模型输出逐字一致。

## 10 人体验观察表

先邀请5人观察，修复重复问题后再找5人，避免一开始扩大样本。每位预计15–20分钟，观察者尽量不提示。用户知情、自愿；不收 API Key、聊天私密内容或完整日志。

| 字段 | 记录方式 |
| --- | --- |
| 匿名编号/路线/已有工具 | P01–P10；API/Ollama/Agent；是否已经能在原工具中使用 |
| 安装完成 | 是否成功；卡点 |
| 连接成功 | 是否 Ping 成功；从安装到连接所需分钟；错误文案 |
| 第一条有用回答 | 是否完成；用户如何判断有用；所需分钟 |
| 独立追问 | 能否在不提示下完成；最困惑的步骤 |
| 真实下一项任务 | 用户会用它做什么，而非观察者建议 |
| 一周后自愿回访 | 是否再次使用；几次/哪些任务（本人回忆） |
| 不再使用的原因 | 后端配置/回答质量/附页质量/不需要/其他 |
| 愿意推荐的理由 | 保留用户原话；不要诱导好评 |

一周回访需要用户事先同意，由维护者手动执行。无遥测，不加定时通知或外部联络自动化。

## 一个月的实验

第1周：5–10人首次使用观察，按出现频次与任务阻断程度排序问题。第2周：两个允许自荐的中文开发者渠道，各测试一个任务视频与同样的上手路线。第3周：修复最常见阻断，记录经用户同意的匿名案例。第4周：重复表现较好的渠道，比较新一批是否也完成任务并回来使用。

渠道表记录：发布日期、渠道、短片版本、定位句、安装页点击（渠道自有统计可得时）、自愿反馈数、成功完成任务人数、一周回访参与者及再次使用人数。不同分母单独报告，不把体验群参与者的留存外推到所有安装者。目标是验证一批每周真实使用的人；“100周活跃”是方向而非本轮增长预测。
