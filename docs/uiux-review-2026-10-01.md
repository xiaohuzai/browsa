## 最值得做的设计调整

1. **先让当前模型可辨。** 390px 视频会话中，顶栏选择框仅约 104px，扣除内边距和箭头后约 68px 留给文本，实际只看到“My OpenAI”，`gpt-4o` 和状态被截断。推荐让“模型 + 会话 + 更多”成为窄侧栏的顶层入口；搜索、多选、设置放进带文字的更多面板。视频时间线作为有视频时的上下文入口保留优先级。继续沿用原生模型选择器，打开后保留完整模型/服务商/连通状态，避免因自定义下拉引入不必要复杂度。
2. **会话操作更容易发现。** 在鼠标和键盘焦点状态显示同款操作区，补直接重命名入口，继续保留双击/F2。无需增加常驻教学文本；操作本身应表达用途。
3. **让新对话的图形语义一致。** 输入区左侧垃圾桶的可访问名称是“新对话”，图形却容易理解为删除。建议换为同一 SVG 系统内的新建对话图标，沿用现有清空确认行为。
4. **设置页分组更安静。** 保留已有 Provider 分组和两列桌面布局；窄宽度让组标题与说明上下排列，避免葡语说明形成很窄的长段落。统一小型增删/显示密钥按钮的点击区域和 SVG 风格。

推荐分两批：先修上表已复现问题；再做顶栏与会话入口的短设计确认。这是现有流程的局部改进，不建议同时替换主题、增加动画库或引入新 UI 框架。

## 技能资料的应用范围

技能本地查询验证了 Compact Label Overflow、Text Reflow and Spacing、Chip Collection Reflow、Focus States、Color Contrast、Web Target Size 的适用性。两次导航层级查询返回了不适合平面侧栏的面包屑/固定导航建议，未采用；顶栏入口层级建议依据当前产品布局和技能 quick-reference 的 content-priority / visual-hierarchy 作出。

Web 控件最低 24 CSS px 与原生 iOS 44pt / Android 48dp 是不同规范。browsa 为桌面 Web 扩展，不以手机按钮规范机械判定全部控件。图标 send 的白色与橙色约 3.84:1，符合 3:1 非文字图标阈值；因此没有把它误报为普通文字对比度失败。
