# CWS 实际填写包

**交付目标**：生成 `store-assets/cws-update-vX.Y.Z.md`，用户打开 CWS 后能按“页面 → 语言 → 字段”找到位置、复制完整内容、完成填写。软件包元数据、Dashboard 可填内容和内部核对信息各有明确位置。

先读 [字段地图与官方依据](references/dashboard-fields.md)；生成时使用 [填写包模板](references/template.md)。用户描述的当前页面优先于旧包中的栏目。没有查看登录后的 Dashboard 时，如实标注“按官方字段文档整理，未核对当前账号界面”，不声称真机实测。

## 已纠正的字段事实

- **没有独立的 What's new / 此版本中的新功能填写步骤**。官方商品详情文档允许在详细说明中写 changelog，但它不是独立字段。默认只把更新清单放在内部核对附录；用户希望商店展示更新摘要时，把简短摘要直接融入各语的完整详细说明，不让用户拼接两段。
- **名称和简短说明来自上传包**的 `manifest.name` / `manifest.description`，本项目通过 `_locales/*/messages.json` 解析。交付包列实际值供核对，注明“软件包提供，无需在 Dashboard 粘贴”。需要改时提出具体包内文案修改；没有授权不 bump、不另发包。
- **权限理由按上传包的权限生成**，包括 `permissions`、`optional_permissions`、主机权限与后台实际显示的理由框；不预设 12 个框。
- **隐私权是数据类型勾选 + 多项用途认证**，不是一个“是否收集个人数据”的总开关。“无遥测、开发者无服务器”不等于没有处理用户数据。本地处理也需披露；网页内容、浏览活动、认证信息等逐项核对用途和流向。
- **截图与视频可本地化**；默认资源与语言覆盖资源分开列。小宣传图块和 Marquee 宣传图块不可本地化。素材位填文件或 YouTube URL，不填本地 mp4 路径。

## 1. 取事实与基线

1. 确定用户这轮是“只生成文案”“已上传包后补填”还是“准备发新包”。已上传时把上传步骤标为已完成。
2. **本轮目标版本以用户指定或已上传的 ZIP/版本信息为准**。没有时读取当前 manifest 和 git tags 并说明差异；不默认最新 tag +1，也不擅自建议重新上传已完成的软件包。
3. 从 `store-assets/` 选语义版本最新的 `cws-submit-v*.md` / `cws-update-v*.md` 作文案基线；五语补充基线用日期最新的 `cws-listing-locales-*.md`。`docs/cws-listing.md` 是初版策略文档，不作现役文案。**旧包只提供文案，不定义 Dashboard 字段，也不能证明线上版本或审核状态。** 没有本地基线时用当前包、README 与用户提供的商店信息，明确哪些现值未核实。
4. release 流程见 `.github/workflows/release.yml`：日常分支 manifest 与已发布 tag 可能不同；对照上传包，而不是把分支 version 的差异当成功能回退。商店线上版本不能仅凭最新 tag 推断。
5. 读实际 manifest 的权限、注入配置、最低浏览器版本；读七个 locale 的包内名称与简短说明。对照商店基线到目标代码的用户可见变更，包含尚未进商店的中间版本。不要只搜 merge commits，仓库可能用 squash：

```bash
git log v<STORE_BASE>..<TARGET_REF> --oneline
git diff v<STORE_BASE>..<TARGET_REF> -- manifest.json
```

6. 查 README、设置与实际数据流，确认能力和 UI 语言。包内七个 locale 不自动证明 UI 翻译完整，更不能照抄旧包的“UI 仅英/中”。

## 2. 逐字段生成

每个字段都有：**页面 / locale / 字段原名 / 动作 / 完整内容或准确现值 / 来源与核实状态**。动作只用：`更新`、`新增`、`沿用`、`已完成`、`不适用`、`待确认`；具体上传方法写操作说明。沿用项无需重复粘贴，但完整填写包仍给已核实的现值供核对。旧包草稿只标“文案参考”，未经核对不能写成在线现值。

- **商品详情**：按语言下拉提供七语完整详细说明，语义对齐、不把中文写成英文行话；沿用基线小节结构，新行为补入对应小节。分类按实际下拉选项和线上现值，不能虚构主/次分类。
- **图片与视频**：逐项列商店图标、默认截图、小宣传图块、Marquee 图块、默认宣传视频，以及各语截图/视频覆盖。截图选择准确文件和尺寸；新素材取实际输出文件。视频遵循项目 [promo-video](../promo-video/SKILL.md) 的当前七语上传清单，选本轮已上传且处理完成的 YouTube 视频；不硬编码旧 62s 文件，不给 playlist 链接代替单个视频 URL。
- **链接与内容分级**：分别给首页 URL、支持 URL、官方 URL（仅能选择已验证网站）及成人内容选项。按现值和产品事实填写，不替用户假定网站已验证。分类或链接现值未知时，未要求变更的项明确“保留后台现值，不改动”；需新增或修改的必填项标待确认。可选官方 URL 无已验证网站时可留空，已有选择则保留；不让可选空项阻塞提交。
- **隐私权**：单一用途说明、每个权限理由、远程代码选择、逐项数据类型、多项用途认证、隐私政策 URL。用户自己的模型/Agent 端点也是数据流的一部分。问卷与代码、隐私政策矛盾时明确指出具体项并给建议，未核实答案标待确认；不自动沿用旧包的“全部否”。仅选择确实满足的认证；已确认不满足则写“不勾选（不满足）”、说明需要修正的用途，不能标可提交。认证文案与数据类型名称以实际后台为准，官方参考见字段地图。
- **测试说明 / 访问权限**：这是给审核员的可选非公开信息。提供完整短说明，区分“无需 Key 可检查的附加/界面流程”和“回答功能需要配置模型或 Agent”，不能把无 Key 路径声称为完整 AI 测试。账号名/密码只在实际需要且用户提供专用测试账号时列，不能用个人 Key 或虚构凭据。
- **分发**：可见性、地区及后台实际出现的付费/免费选项。保留既有用户选择，不默认改变分发范围。

复制块只放将要粘贴的文字/URL，不放字符统计、解释、替换建议或内部 PR 列表。选择框直接列应选的实际选项；上传框列文件绝对路径和对应位置。尚缺的事实放文首待确认清单，不把 `<待补充>` 混入可粘贴内容。存在影响本次填写或提交的未知项时，不把包叫“完整可提交”；保留未改动现值、可选留空项不自动阻塞提交。

## 3. 七语与素材纪律

- 语言族：`en / zh_CN / ja / ko / es / pt_BR / ru`。Dashboard 语言来自上传包 `_locales/<code>/`；新增目录要进入实际上传包后才出现，不指引寻找独立“添加翻译”按钮。
- **每语一份完整详细说明**，提交顺序涵盖全部七语；名称/简短说明只是各语软件包核对表。先确认后台是否存在语言覆盖：已有覆盖则沿用该覆盖，确认没有才沿用默认，未知则保留后台现值并标待确认。本地缺文件不能证明后台没有覆盖，不编造回退后的 What's new。
- 每语在当前语言下完成“详细说明 + 该语覆盖素材”，按实际后台方式保存并确认保留后再切换下一语；不假定语言切换自动保存，也不先跨七语修改后才集中保存。
- 按本轮素材自身分辨率考虑截图、宣传图块、GIF、视频。CWS 只上传支持的图片和 YouTube 链接；GIF/官网 mp4 是项目素材，不当作 Dashboard 上传位。是否需要重拍及原因放核对附录。
- 本项目商店截图/宣传图块源在 `dev-preview/banners/`，按现有 `render.mjs` 生成，旧输出先保留备份；实际输出在 `store-assets/`。不因生成文字填写包就全量重拍。
- 视频换源：新视频处理完成、可公开或不公开访问 → Dashboard 换为新链接 → 确认生效。历史视频按 promo-video 的播放列表策略保留，不指引删除旧视频。
- 名称 ≤75、简短说明 ≤132；测试说明暂按本项目过去后台观察的 ≤500 保守生成，**不称其为官方通用上限**，用户当前计数器优先。其他上限只从真实控件或官方文档取，不捏造。
- 统计实际输出的字符数，写在复制块外。已有 `store-assets/locales-count-check.mjs` 时运行；不存在则直接用脚本统计，不给一个无法运行的命令。

## 4. 本项目商店文案经验

- 历次 Yellow Argon 拒审曾点名站点名、文件扩展名、模型/工具名的并列堆砌。避免正文列多个第三方产品名，优先用功能名词；改一语后扫七语同款表达。这是本项目的保守整改经验，**不是“只出现一次就一定过审”的官方保证**。
- 不主动重命名已经在线的名称，也不把旧商店名称直接覆盖当前包里的 `browsa`。新名称修改必须落到具体包内值并说明影响。
- 描述与用户可见行为一致；不新增收费/限额类免责，不虚构能力。广告式评分引导不是更新填写任务，默认不添加。
- 拒审后按拒审原文定位实际字段，一次修齐相关七语内容；不能再写“优先替换 What's new”。同一 item 更新，避免删除商品而丢失安装与评价。

## 5. 交付前验收

1. 每段待填写内容能映射到一个真实字段；软件包提供的值明确无需粘贴。
2. 七语详细说明齐全；每个复制块是完整替换内容，没有省略号/模板变量；名称、简短说明、测试说明长度核验。
3. 权限理由与实际包、数据问卷与代码/隐私政策一致；已上传步骤不重复。
4. 所有素材文件存在且尺寸正确；YouTube URL 指向本轮单个视频，链接已核实或明确待确认。
5. 提交顺序按后台页签，覆盖七语、资源、链接、隐私、测试、分发；默认沿用项不要求重填。
6. 内部变更、PR、素材取舍和来源放附录，不混入 Dashboard 文案。默认只交付本地填写包；实际上传、保存和提交按用户授权执行。

交付摘要直接说“本轮在哪些页面填哪些字段、哪些沿用、还有哪些待确认”，附绝对路径链接。生成流程修改不自动发版或提交商店。
