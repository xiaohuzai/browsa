# YouTube 批量上传与版本维护

用途：按用户要求，通过 YouTube Studio 上传新片、填写已有视频或维护播放列表。当前只有浏览器操作入口，没有已配置的 YouTube API/OAuth 上传工具；skill 提供操作流程，不是后台无人值守上传服务。需要可控制且已登录目标频道的浏览器；登录/验证码/系统权限由用户按实际需要完成。不建立新的 OAuth 项目，也不从浏览器提取 cookie 或 token。

账号由用户自行登录，密码、验证码无需发到聊天，也不写进 skill、台账或 Git。使用该浏览器已有的登录状态；不假定 Chrome 的登录状态会共享到内置浏览器。用户完成登录及所需控制权限后，读取 Studio 确认频道，再继续上传。

以 `docs/youtube/<version>/published.json` 为每版记录，新版建立新目录；相同版本换了视频文件且 SHA-256 改变时增加 revision，保留旧记录。新增视频产生新 YouTube ID，不能通过上传覆盖旧 URL。

## 浏览器操作

1. 用 `cua` 获取用户指定/已登录的浏览器，打开 `https://studio.youtube.com/` 并读取页面。确认频道与目标列表一致；若未登录或 Computer Use 权限未就绪，说明需要用户完成的具体动作，不宣称具备当前上传权限。
2. 每个文件开始前检查台账及 Studio 内容页。已有相同版本/语言/revision 的 ID 就打开详情继续；有未完成草稿就续填。网络中断先检查传输状态：页面提供重新选择同一文件/恢复上传时，用相同本地文件恢复；只有页面明确失败且无法恢复、或已确认原条目不存在，才创建替代上传。保留失败 ID/原因并记录 replacementOf；状态不明先报告，不能用无限重传制造重复视频。ID 是否存在要从可见页面确认，不只按标题猜。
3. 点击当前页面的“创建/上传视频”，通过已观察到的上传控件传文件。先读运行时 `file-uploads` 文档；优先 filechooser，传本机绝对路径。当前支持的示例：

```javascript
const chooserPromise = tab.playwright.waitForEvent('filechooser', {timeoutMs: 10000});
await uploadControl.click(); // 来自本轮页面观察的 locator
const chooser = await chooserPromise;
await chooser.setFiles(['/absolute/path/to/approved-video.mp4']);
await tab.getAXState();
```

`uploadControl` 从当前 DOM/AX 选择，不能照抄旧元素编号。当前接口没有 locator.setInputFiles；原生 Chrome 的文件选择器用已返回的 App API 操作。不能把一种浏览器的 API 硬套到另一种。

4. 视频 ID/详情链接一旦可见就记录；逐条填入对应语言标题和完整说明，选择实际海报，设置视频语言。当前是无旁白产品演示，语言按片中文字；先设置该语言的原始标题/说明。面向技术用户的产品演示选择“不是面向儿童制作”，如后续素材定位改变重新判断。类别可用“科学和技术”，不把付费推广/AI 合成披露/字幕选项一律勾选；按真实素材、用户说明和页面要求判断。
5. 核对标题、说明、语言、缩略图、受众、可见性，以及是否有缺失字段。保存为用户要求的状态；默认私享。不跳过版权/处理错误；草稿、上传中、处理中、检查通过、已发布是不同状态，逐项记录。
6. 顺序处理七语。短轮询期间报告进度，避免长阻塞。单条有问题就保留其 ID 和状态，其他已授权且独立的条目可继续；整体未完成不宣称七条已完成。浏览器界面变了先读新状态，不靠反复点击碰运气。

## 主列表与历史列表切换

先准备完整新七语并逐条验证；私享批次只在 Studio 保存，不替换现役主列表。公开或不公开的七语已就绪且用户要求更新主列表后：

1. 读取主列表，按既有台账识别上一套七语。只处理这些已核对 ID；遇到陌生视频先确认用途，不删除、不搬走无关内容。
2. 在所属频道找已记录的历史列表；找不到时按用户已选择的归档方式创建“browsa 历史演示”并记录 ID，默认不公开。将旧七条全部添加过去并验证成员关系，此时仍保留在主列表。
3. 新七条先加入主列表并验证可访问，再移出已归档的旧七条，避免主列表出现空档。操作中可短暂超过七条；完成态仅新七语，建议顺序 zh/en/ja/ko/es/pt-br/ru。
4. 不删除旧视频、不自动改变旧视频可见性。历史标题含语言/日期可区分版本；当前旧标题缺日期时依据台账区分，用户没有要求时不回改。
5. 任何迁移失败保留新旧记录，报告哪一步未完成；重试先核对实际成员关系，不重复创建历史列表。公开列表不能让私享视频成为可播放条目。

网页发生修改后保存可审阅截图（本地 `store-assets/promo/<version>/youtube/`），最终给出已完成/未完成清单、七语链接和证据；按当前浏览器工具文档在回复里展示结果截图。没有实际登录上传测试时明确写“流程已加入，线上上传尚未实测”。只改 skill 不需要制造一次真实上传来验证。

上传不顺带修改 README/官网/CWS。用户要求换推广入口时才用已验证的新语言 URL 更新对应入口；未发布或私享的链接不能冒充公开演示。
